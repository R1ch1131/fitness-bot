# FitPulse Weight · Scriptable

Виджет показывает последний импортированный вес Apple Health, прогресс от 103 до 80 кг,
сколько уже сброшено и сколько осталось. Поддерживает маленький и средний размеры.

После деплоя откройте на iPhone:
https://fitness-bot-9f8m.onrender.com/widgets/weight

На странице есть кнопка копирования скрипта и шаги установки. При первом запуске
скрипт запрашивает существующий HEALTH_IMPORT_TOKEN; в исходники его вставлять не нужно.
Он хранится в Scriptable Keychain. Повторный ручной запуск позволяет изменить или удалить ключ.
Настройки команды Health Export Kit и Render менять не требуется.

Данные: GET /api/widgets/weight с Authorization: Bearer <token>.
Без ключа запрос отклоняется до чтения данных. Ответ не содержит сна, книг, токенов
или полной истории взвешиваний. API не обращается к Gemini, Hevy или YAZIO.
Скрипт запрашивает только этот HTTPS-адрес; перенаправления отключены.

При отсутствии сети используется последний успешный ответ из FileManager.local(),
с видимой пометкой «Нет связи» и датой взвешивания. Ошибочный ключ очищает этот кэш;
смена или удаление ключа также очищает его. Отсутствие веса не заменяется демонстрационным числом.
Не нужно держать сайт открытым. Новые замеры появляются после отправки команды экспорта.

Скрипт просит следующее обновление через 5 минут, в том числе после ошибки;
iOS определяет фактическое время. Нажатие открывает ссылку на страницу недели:
система может открыть её в Safari. Это виджет приложения Scriptable, а не расширение PWA.

Проверка без iPhone:

```sh
node --test integrations/scriptable/test-widget.mjs
python -m unittest test_health_weights
```

Скрипт проверен с заменами API Scriptable, нативную отрисовку и фоновое расписание
нужно проверить на iPhone после установки.

Документация: [ListWidget](https://docs.scriptable.app/listwidget/),
[Keychain](https://docs.scriptable.app/keychain/), [Request](https://docs.scriptable.app/request/).

## Второй вариант: FitPulse Overview

Установка: https://fitness-bot-9f8m.onrender.com/widgets/overview

Создайте **отдельный** скрипт FitPulse Overview. Используется средний прямоугольный размер;
маленький размер показывает подсказку о выборе размера. Слева вес и прогресс, справа три
последних успешно отправленных push (заголовок, сокращённый текст, время по Омску).
Нажатие на запись открывает её ссылку. Ключ общий с первым скриптом, кэш раздельный.

API /api/widgets/overview требует тот же ключ. История хранится в notification_history
через существующее локальное/Redis-хранилище, максимум 50 записей. В виджет выдаются три.
Запись создаётся один раз после успешной отправки хотя бы в одну подписку, не на каждое устройство.
Ошибочная отправка в историю не попадает. Сбой записи истории не провоцирует повтор успешного push.
Ни ключи подписок, ни prompt самочувствия в истории не сохраняются.
Старые уведомления до этого обновления восстановить нельзя. История подтверждает приём push-сервисом,
а не доставку/показ на экране. Обновление запрашивается через 5 минут, фактическое время решает iOS.
Внизу отображается время загрузки, при сбое — время сохранённой копии. Вес актуален на дату замера
и изменяется после экспорта Apple Health; уведомления актуальны на момент загрузки виджета.

## Обновление от 10 ноября 2026

Оба виджета используют актуальную ночную палитру приложения: #19221f, #e6eee8,
#79c5a6 и #33473b. Выравнивание блока веса и крупные уведомления сохранены.
Запросы обходят HTTP-кэш; сетевой сбой/408/429/5xx/неверный JSON повторяются один раз.
Ошибочный ключ не повторяется и очищает кэш. Фоновые попытки ограничены тайм-аутами 10 и 5 секунд;
при ручном запуске первая попытка допускает 20 секунд. При неудаче остаётся честно помеченный кэш.
API прямоугольника читает вес и журнал параллельно, без общего кэша личных данных.

↻ и нижняя строка запускают свежую загрузку и предпросмотр через Scriptable без промежуточного меню.
Это не гарантия немедленного обновления уже размещённого виджета: его расписание контролирует iOS.
Системный относительный таймер показывает возраст сохранённой сводки и обновляется периодически
без нового запроса к серверу. Дата замера веса выводится отдельно. Сохранённые копии не переименовываются
в свежие при ошибке сети. Пять минут — только запрошенное ближайшее время, не обещанный интервал.
