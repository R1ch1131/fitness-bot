# Сон Apple Watch → FitPulse через «Команды»

Серверная интеграция подготовлена, но сама команда ещё не установлена на iPhone.
Safari и установленное веб-приложение не читают HealthKit напрямую. Здесь данные
читает приложение «Команды» с вашим разрешением и отправляет их на ваш сервер.
Команда состоит из готового экспорта Health Export Kit и отправки файла.
Её автоматический запуск нужно проверить на вашем телефоне. Названия действий могут немного отличаться в разных версиях iOS.

## 1. Настройка Render

В Environment сервиса добавьте `HEALTH_IMPORT_TOKEN`. Значение — случайный секрет
не короче 32 символов. Например, локально его можно создать командой Python:

```sh
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

Сохраните ключ в надёжном месте. После применения переменной Render перезапустит
сервис. Этот же ключ нужен в команде iPhone и на странице «Неделя» приложения.
Он защищает импорт, чтение и удаление сна. При настроенном ключе история чата
тоже требует этот ключ: ответы ИИ могут содержать сведения о сне.
Не вставляйте ключ в URL, исходники GitHub или общедоступные ссылки на команду.

## 2. Короткая команда через Health Export Kit

Поддержан настоящий формат Health Export Kit **schemaVersion: 2** (проверен на
экспорте приложения 1.0.18). Вручную разбирать фазы и собирать словари не нужно.

1. В «Командах» добавьте действие Health Export Kit **Export**:
   период **«Последние 7 дней»**, формат **JSON**. Если можно ограничить категории,
   выберите только сон. Сервер игнорирует остальные категории, даже если они есть.
2. Добавьте отдельное действие **URL** и вставьте адрес:
   `https://fitness-bot-9f8m.onrender.com/api/health/sleep`.
3. Добавьте **«Получить содержимое URL»**. Вверху выберите результат действия
   **URL** со значком цепочки. Не выбирайте там результат Export и не переименовывайте
   переменную экспорта в адрес сервера.
4. Метод — **POST**. Заголовки:
   - `Content-Type`: `application/json`.
   - `Authorization`: `Bearer ВАШ_КЛЮЧ` (один пробел после Bearer).
5. **Тело запроса → Файл**. В поле «Файл» выберите результат первого действия
   **«Экспорт данных здоровья»**. JSON-файл отправляется целиком, без преобразования
   в строку и без обёртки `samples`.
6. Для первого запуска добавьте в конце **«Быстрый просмотр»** результата запроса.
   Успешный ответ содержит `status: ok`, `imported_nights` и `imported_at`.
   Ошибка содержит `detail`. Не заменяйте ошибку сообщением об успешной отправке.

Итог: **Export → URL → Получить содержимое URL → Быстрый просмотр**.

На первом запуске разрешите Health Export Kit чтение сна. Серверная версия с
этим импортом должна быть опубликована до проверки отправки команды.

### Если отправка долго ждёт или возвращает ошибку

Нажмите квадрат остановки. Для отдельной проверки добавьте после Export действие
**«Сохранить файл»** с результатом экспорта. Этот JSON можно использовать для проверки структуры экспорта.
В интерфейсе приложения ручной загрузки файлов нет: сон отправляет команда iPhone.
Никакая команда не может обойти запуск спящего сервера Render или отсутствие
обновления на сервере. Ключ и полный JSON не должны выводиться в публичные логи.

### Что именно поддерживается

Читаются только `meta.timeZone`, `rangeStart`, `rangeEnd`, `schemaVersion` и
интервалы из `sleep.sessions[].stages[]`. Даты вида `10-21 23:37:44` восстанавливаются
по периоду экспорта и часовому поясу; переход через Новый год поддерживается.
Неоднозначные или неизвестные форматы отклоняются с понятной ошибкой.
Остальные категории, потоки пульса и текст `meta.notes` не сохраняются и не
передаются ИИ. Сон без записанных фаз не восстанавливается по догадке.

Также сохраняется минимальный формат для других команд:

```json
{
  "samples": [
    {"start": "2026-10-25T23:00:00+06:00", "end": "2026-10-26T07:00:00+06:00", "stage": "core"}
  ]
}
```

Фазы: `core`, `deep`, `rem`, `asleep`, `awake`, `in_bed`;
также поддерживаются имена HealthKit `asleepCore`, `asleepDeep`, `asleepREM`,
`asleepUnspecified`, `inBed` и числовые значения 0–5.

## 3. Подключение в веб-приложении

Откройте **Неделя → Сон · Apple Watch**, вставьте ключ и нажмите «Подключить сон».
Ключ хранится локально на этом устройстве. Он передаётся только вашему серверу
в заголовке запросов; самому ИИ ключ не передаётся. После отправки команды нажмите
«Обновить сон»: обновятся данные и картинка недели. Кнопка «Обсудить с ИИ» использует
сон только при подключённом ключе. Обычный чат также получает последние семь дней сна
при авторизованном запросе. Обработка запросов ИИ выполняется настроенным Gemini API.

«Отключить устройство» удаляет сохранённый ключ, но не историю на сервере.
«Удалить данные с сервера» удаляет импортированные записи сна. Уже сохранённые
ответы с этими сведениями остаются в истории чата; её можно очистить отдельно.
Отключите ежедневную команду, если не хотите повторного импорта после удаления.

## 4. Ежедневное обновление

После успешного ручного запуска создайте личную автоматизацию «Команд», например
на утро после пробуждения. Выберите запуск этой команды и доступный в вашей версии
iOS режим запуска без подтверждения. Доступ к «Здоровью» зависит от разрешений и
состояния блокировки телефона; проверьте запуск с заблокированным iPhone отдельно.
Если данные недоступны, используйте ручной запуск после разблокировки. Сервер не
может заставить iPhone выгрузить данные или гарантировать точное время запуска.

## Как считаются данные

- Сон относится к дню пробуждения в окне **с полудня предыдущего дня до полудня
  выбранного дня по Омску**. Дневной сон после полудня попадёт в следующее окно.
- «В постели» не добавляется ко времени сна. Интервалы сна объединяются, дубли
  не суммируются; детальные фазы имеют приоритет над общим «сон».
- Повторный импорт заменяет выбранные ночи. Нужно передавать все интервалы каждой
  затронутой ночи, а не один новый фрагмент. Пустой импорт ничего не удаляет.
- Хранятся до 400 дат. Нет записи — нет данных, а не «0 часов сна».
- Данные часов — оценка, а не медицинский диагноз. ИИ должен учитывать полноту
  истории и самочувствие, не диагностировать заболевания по процентам фаз.
